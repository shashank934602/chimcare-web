## What a 200 does and does not prove

It proves the page was found, built and served — which is the failure that was most likely. The route
data is a file with nothing in the code pointing at it, so the build would normally omit it from the
deployment. Had that happened, every one of these would have returned 404 while working perfectly in
development.

It does **not** prove the page is correct. Three things are true of pages that return 200:

- **52 of them resolve no service links at all**, because WordPress publishes no service
  pages for that city. Those pages render without a service directory.
- **Every page emits zero internal links**, including the 948 that hold real
  service URLs in their data. The cards render as plain text.
- **Breadcrumbs point at state pages that do not exist.** Only `/locations/mn/` resolves, so 986 of
  these pages link to a 404.
